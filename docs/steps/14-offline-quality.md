# 14. Офлайн-режим и проверка качества

[На главную](../../README.md)

## Задача

Сделать загрузку новостей устойчивой к ошибкам сети, Room и минификации release-сборки.

## Что изменилось

- Добавлены Room-сущности для новостей, страниц и порядка элементов.
- Добавлен `OfflineFirstNewsRepository`.
- Кэш ограничен сроком в семь суток.
- Поля Gson DTO получили явные `@SerializedName`.
- Ошибка записи в кэш больше не скрывает свежий ответ сервера.
- Добавлены unit-тесты кэша, fallback-логики и JSON-десериализации.
- Добавлены instrumented-тесты основных переходов.

## Как работает код

Repository сначала обращается к API. При ошибке он ищет актуальные данные в Room. Если кэш найден, UI получает `isFromCache = true` и показывает офлайн-баннер.

После успешного ответа данные сохраняются в Room. Эта запись является best-effort операцией. Ошибка диска не меняет уже полученный сетевой результат. Отмена корутины не перехватывается.

`RoomNewsLocalDataSource` сравнивает `cachedAt` с текущим временем. Страницы и отдельные публикации старше семи суток не возвращаются.

R8 может удалять поля, доступные только через reflection. Поэтому каждое поле DTO имеет `@SerializedName`. Проверка release включает анализ `usage.txt` и `mapping.txt`.
